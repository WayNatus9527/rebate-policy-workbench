# 第一阶段交付范围

仓库名称：rebate-policy-workbench  
阶段：人工配置与确定性规则验证基础  
状态：可运行试点，尚未完成全部PRD及大模型Agent功能

## 已交付

- 活动、成员、核算组、两类产品范围、分产品比例和阶梯配置。
- 政策文本与交易JSON导入、人工确认及服务端校验。
- 集团共享系数与子抬头分别返利的模拟试算。
- 退货同步扣减台阶金额与返利基数，不执行扣款或奖励追回。
- 持久化存储、乐观锁、提交审批、角色分离约束和配置导出。
- 模拟快照及外部已完成核算历史导入，禁止覆盖历史结果。
- SAP接口预留；不进行实际对接、支付、回读或激活。
- 只读WebMCP工具，读取当前配置摘要与校验问题。

## 验证记录

- 24项自动测试通过。
- 本地接口集成测试通过，覆盖认证、试算、并发冲突、版本失效、历史不可覆盖及SAP禁用。
- TypeScript类型检查和部署构建通过。
- 浏览器验证退货案例：A奖励10,000元，B奖励12,000元，合计22,000元；历史快照显示一致。

## 继续开发

下一阶段重点是政策文件解析、带证据的规则提取、歧义识别与追问、模板推荐，以及调用已有校验和试算工具的Agent工作流。目前没有接入大模型，也没有自动从自然语言生成配置。

多人审批需要另行配置实际访问范围及审批人。税、日期、跨期退货、不同产品退货比例归属及舍入约定需确认后才能用于正式业务；当前假设和边界详见README。

## 仓库内容

保留源码、依赖锁文件、数据库迁移、测试、接口文档及明确标记的虚构示例。依赖目录、构建产物、本地数据库、测试截图、环境变量文件及类型检查缓存不上传。原始PRD和评审文档位于项目父文件夹，不在此源码仓库中。

`.openai/hosting.json`中的project_id是现有私人Sites项目的标识，不是凭据；它用于继续维护当前部署。克隆后如需创建独立Site，应先替换部署身份，避免误更新原项目。
